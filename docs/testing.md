# Testing coverage

Current coverage by area. Add to this file when you add tests.

## Unit (`src/lib/__tests__`, `src/types/__tests__`)

- **Tenancy:** `tenant-scope` covers every operation type (where-merging for reads, updates, deletes, counts and aggregates; create/createMany data; upsert), the same-org explicit filter, rejection of another org, operator filters, relation connects, moving rows between orgs, a missing organisation, and pass-through for non-tenant models. `tenant-db` checks the extension wiring and that it throws before querying. `tenant-context` covers 401 without a session, 403 without an active org or membership, context building, and unknown role/tier downgrades. `requirePermission` is covered too.
- **RBAC** (`rbac.test.ts`): the full permission matrix, `hasPermission` edge cases, `isMemberRole`, `assignableRoles`.
- **Plans** (`plans.test.ts`): tier parsing, documented Free limits, limits and features never shrink up the tiers, `canAdd` including unlimited, `upgradeTierFor`, feature inheritance, `minimumTierFor`, every feature labelled and never Free-gated, pricing sanity, formatters. `requireFeature` is in `tenant-context.test.ts`; the audit log plan gate (Free/Pro refused, Studio/Facility allowed) is in `audit.test.ts`.
- **Studios and rooms** (`studios.test.ts`): list, get (404), create (plan limit, viewer 403, validation before DB), update (404 when nothing matched, audit metadata), delete (404), room create (cross-org studio 404, org-wide room limit), room update/delete, usage.
- **Equipment** (`equipment.test.ts`): filters become the query, create (audit, viewer 403, plan limit, cross-org room 404, validation), update/delete (cross-org 404, viewer 403, photos removed). **Import/export/valuation** (`equipment-io.test.ts`): alias and price parsing, all-or-nothing row errors, plan limit, formula-safe export, totals/retired/unpriced, Pro gate. **Attachments** (`attachments.test.ts`): magic-byte sniffing, type/size/count/storage limits, cross-org 404 before storage is touched. **CSV** (`csv.test.ts`).
- **Mic catalogue** (Phase 2): `charts.test.ts` (first-order pattern maths, idealised polar, half-plot mirroring, rear nulls, log interpolation, curve merging); `mics-dsp.test.ts` (FFT, 1/3-octave response flat for an impulse and rolling off for a low-pass, gain-independent, polar relative to 0°, WAV 16/24-bit, robots.txt parsing, link checker uses HEAD, an identifying user agent and Crawl-delay); `mics-schemas-seed.test.ts` (provenance rules, update schema never applies defaults, per-maker cap, **the shipped `data/mics` files parse, contain no invented numbers and give every populated field a source**, ingest creates drafts and never touches published rows); `mics-admin.test.ts` (publish gate blockers, LLM-drafted attestation, status transitions, create/update/queue); `mics-catalogue.test.ts` (published-only reads, spec table shows gaps and stated conditions, ribbon phantom warning); `mics-locker.test.ts` (cross-org item and unit 404, non-mic and already-linked items, unpublished model 404, plan limit only for newly created items, rollback, matched-pair rules, viewer 403); `platform-admin.test.ts` (verified email only, 404 for non-admins).
- **AI layer** (Phase 3, no network or API key needed; a fake provider stands in for the model): `ai-core.test.ts` (canonical hashing ignores key order, number extraction and grounding allow copied values, rounding and kHz but flag invented ones, sliding-window limiter per key, model config); `ai-usage.test.ts` (month key in UTC, allowance reserve/refuse/give-back, creation race retry, token recording, scoped through `tenantDb`); `ai-service.test.ts` (cache hit is free, needs no key and is not rate limited; miss generates, validates, stores and records tokens; one retry with the rejected reply fed back, then fail closed with nothing stored and the request handed back; provider errors become 503; allowance, rate-limit and missing-key ordering; viewer 403); `ai-anthropic.test.ts` (structured-output request shape, no `temperature`/`thinking`/`tool_choice`, thinking blocks skipped, bad JSON and truncation retryable, refusal not, SDK errors mapped without leaking text); `mics-ai.test.ts` (facts hold only catalogue values and are order-independent, a spec change changes the hash, prompts keep data out of the system prompt, **an invented number or an unsupplied mic slug is rejected**, spec comparison rows and differences, overlay curve choice, 2 to 4 mic resolution).
- **AI spend guards** (`ai-guards.test.ts`; service and route tests cover the wiring): daily cap reserve/refuse/give-back and a cap of 0, UTC day key, junk cap values fall back to the default, `AI_ENABLED=false` beats everything including an override, the local provider is built only in development and needs a model, the local request shape (JSON-schema format, local model id, bounded `max_tokens`, no credentials), fenced JSON, prose and truncation retryable, server-down and missing-model messages; in the service, a paid call reserves and records against the platform, a free provider does not, a refused org spends no platform budget, a cache hit reserves nothing, and every failure hands both requests back.
- **Recommendations** (Phase 4, ADR 0015; no network, a fake provider stands in for the model):
  - `recommendations-profiles.test.ts`: every profile and technique is complete and in range, hints contain no digits, and the classifier (longest keyword wins, whole words, case and spacing insensitive).
  - `recommendations-rules.test.ts`: the pure rules engine. Every exclusion reason, needs-service and fair ranking, SPL (below the band, at it, pads that do and do not cover the gap, unknown on a condenser vs a dynamic, quiet sources never checked), every phantom note including active ribbons, air blast, global phantom conflicts, matched vs unmatched pairs, mixed models, groups of three, pairs with a member in repair, mid-side, Blumlein, Decca, pattern settings and fallback, allocation order and the two unfillable reasons, channel overflow, and order-independence.   - `recommendations-llm-input.test.ts`: aliases are deterministic, no ids, slugs, serials, notes or room names reach the model, user text lives only in one data block, only fillable sources are sent, the cache hash changes with the locker, sources, intent and question and not with the unowned-name guard.
  - `recommendations-prompt.test.ts`: validation. Missing, duplicate or unknown sources, an option from another source, repeated alternatives, placement outside the range or missing, a mic too far for the room, invented numbers (and chosen placement restated in mm, cm or m being allowed), phantom advice for a ribbon, naming a catalogue mic the studio does not own (and an owned one out for repair being allowed), "not answerable" only for questions, the reply schema, and that the prompt keeps data out of the system text.
  - `recommendations-finalise.test.ts`: clashes repaired in order (stereo first), falling back to alternatives then the rules' pick then none, names and warnings from the rules and catalogue, deterministic, unresolvable aliases tolerated.
  - `recommendations-schemas.test.ts`, `recommendations-labels.test.ts`: request and feedback validation, normalisation, presets.
  - `recommendations.test.ts` (service): preview needs only inventory access and stores nothing; create needs `USE_AI`; cross-organisation room 404; nothing stored and the request handed back when the reply is rejected or the save fails; no model call and no spend when nothing is fillable; cache hit, miss on a changed locker, regenerate; the global AI cache is never touched; 16 sources run and 17 are refused. `recommendations-feedback.test.ts`: upsert per person per source, swap rules (exact count, no repeats, not the recommended mics, other organisation's unit 404), viewer 403.
  - `ai-service.test.ts` additions: `generateForTenant` shares the guards and accounting with `generateCached`, hands the request back when saving fails, and `generateCached` / `findCachedAi` refuse a tenant prompt.
  - `recommendations-golden.test.ts`: the evaluation set (`eval/recommendations/`): every scenario's rules expectations, invariants (no unit twice, plan inside candidates, nothing unavailable offered, order-independence) and replays, no network. Fails if `reports/v<promptVersion>.md` is missing. `recommendations-eval-model.test.ts`: the live-evaluation plumbing against a stand-in model.
  - The golden set was mutation-checked: breaking the matched-pair bonus, air-blast penalty, condition penalties, SPL checks, phantom warning, global conflict, channel count, fewest-options-first planning, K cap or availability checks makes a test fail. (Stereo-first planning is a safety net that fewest-first usually makes redundant.)
- **Audit** (`audit.test.ts`), **members** (`members.test.ts`), **seats and health** (`seats-and-health.test.ts`), **auth hooks** (`auth-hooks.test.ts`: default active org, seat-limit invitation rejection, unknown roles, every audit hook), **email** (`email.test.ts`: dev logging, production refusal, ACS send, HTML escaping), **validation**, **api/errors**, **client-api**, **slug**, **safe-redirect** (open-redirect rejection), **navigation**.

## E2E (`e2e/`, Playwright)

Runs against a migrated and seeded database. Against a production build (`npm run start`), set `AUTH_RATE_LIMIT=off` or parallel sign-ins trip the auth rate limiter. Locally it reuses `npm run dev` (or starts it); in CI it runs against a built app (`.github/workflows/playwright.yml`).

- `auth.setup.ts`: signs in the seeded owner and viewer and stores their sessions.
- `sign-in.spec.ts`: unauthenticated redirect with `callbackUrl`, wrong password, return to the requested page.
- `onboarding.spec.ts`: sign up → verify (DB) → sign in → onboarding creates the org and first studio → add a room in metres → Free-plan room limit blocks a second room.
- `studios.spec.ts`: owner views the seeded studio, adds, edits and deletes a room, and sees the activity log.
- `onboarding.spec.ts` › Free plan upgrade prompts: a Free owner sees the activity log as an upgrade prompt (and the API returns 403), invites are blocked by the one-seat limit, and the plans comparison marks Free as current.
- `inventory.spec.ts`: owner adds, searches, edits and deletes an item, sees the asset label and valuation report, exports CSV; viewer has no edit controls and the API returns 403.
- `mics.spec.ts`: catalogue → mic page (sourced range shown, "No frequency-response data yet", polar plot labelled idealised), ribbon phantom warning, add to locker → edit matched group → remove, platform admin adds a mic → submit → publish → visible in the catalogue; viewer can read but not change, and gets 404 for the admin queue page and API. Needs `PLATFORM_ADMIN_EMAILS=owner@kigumi.test` (set in the Playwright workflow and `.env.local`).
- `ai.spec.ts`: mic page shows the AI-generated label and a generate button; the compare page shows both mics, marks differing rows, plots idealised polars and offers a comparison; the picker builds and trims a comparison; unknown mic 404; bad API calls 400/404; usage on the organisation page; a viewer can read but gets 403 generating. It never presses Generate (that costs real allowance).
- `recommendations.spec.ts`: the page checks the locker with the rules and labels it rules-based, works out a source's type from its name, presets, line sources; the seeded stored recommendation shows the AI label, the rules' warnings and the model name; feedback is saved and remembered; history and 404; the API rejects bad input; a viewer can check and read but has no AI button, no feedback controls, and gets 403 from the API. It never presses the AI button (that costs allowance).
- `viewer.spec.ts`: viewer has no edit controls, the API returns 403 for a direct POST, and `/activity` redirects.

Manually verified during Phase 0 against real Postgres (not automated): a second organisation's user gets 404 for every read, update, delete and create on the first organisation's studio and rooms.
