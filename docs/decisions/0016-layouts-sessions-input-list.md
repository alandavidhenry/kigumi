# 0016 — Layouts, sessions and the self-building input list

**Status:** Accepted (2026-11-04). Builds on [0005](0005-canvas-library.md) (react-konva), which stands.

## Context

Phase 5 adds a to-scale 2D top-down room editor and sessions whose input list builds itself from the microphones placed on the layout. It had to store x, y, z, rotation and size now so a 3D view can follow without a migration, and the input list had to stay in step with the layout. Better Auth already owns the Prisma model name `Session`.

## Decision

1. **Coordinates are real-world and screen-independent.** Origin is the room's top-left corner in plan view; x runs along `widthMm`, y along `lengthMm`, and plan-up (−y) is the front wall. Items store their centre (`xMm`, `yMm`), `zMm` (height above the floor; the capsule height for a mic), `rotationDeg` (yaw, clockwise from above, 0 = facing plan-up, 0 to 359), `pitchDeg` (mic aim, negative = down), `widthMm`, `depthMm`, `heightMm?`, all integers. Zoom and pan are view state and never stored (`scaleMmPerPx` from the original plan is dropped). A react-three-fiber view maps (x, z, y) to three.js (x, y, z) with no schema change.
2. **Models.** `RecordingSession`, `Layout`, `LayoutItem`, `InputChannel` and `SessionShareLink`, all tenant models in `TENANT_MODELS`. A **session owns its own layout copy** (`Layout.sessionId` unique, cascade); the only free-standing layouts are templates (`isTemplate`, `sessionId` null), kept in step by a SQL check constraint. A layout's footprint is a **snapshot** of the room at creation, so a past session stays as it was drawn and a template fits any room; "Match the room's current size" updates it. `RecommendationRequest.sessionId` is now a real foreign key.
3. **The input list cannot drift.** A mic or DI item has exactly one linked `InputChannel`. `reconcileInputList` is a pure, idempotent function (`src/lib/sessions/input-list.ts`) run **inside the same transaction as every layout save, template or session copy, and recommendation apply** (`syncInputList`). It creates channels for new items (lowest free number, phantom defaulting from the mic's powering and **never on for a passive ribbon**), refreshes the mirrored fields (source, mic unit, kind) and deletes channels whose item is gone. The item owns the unit and source; the channel owns number, stand, preamp input, phantom, pad, DAW name and notes. Editing a linked channel's source or mic writes through to the item. Numbers never shift on their own; "Renumber" is explicit. Channels with no layout item (line inputs) are manual and never touched.
4. **Warnings are rules, not model text** (`sessionWarnings`): phantom on a ribbon (blocking), phantom needed but off, global-phantom conflict, one unit on two channels, more inputs than channels, a unit double-booked in an overlapping non-cancelled session, a unit not in service, a mic with no unit chosen, an item outside the room. `loadBookings` feeds both these and the recommendation rules' `isBooked` hook (by the session's window, or by the whole day in the studio timezone for a plain `forDate`).
5. **One scene, three renderers.** `buildLayoutScene` reduces a layout to primitives in millimetres. The editor draws with react-konva (client only, `dynamic(..., { ssr: false })`); the session page and public share page render the same scene as plain SVG; PDFs render it with `@react-pdf/renderer`'s `<Svg>` on the server. Konva never loads outside the editor and the server needs no `canvas`. Pickup-pattern overlays reuse `idealisedPolar` and are always labelled "Idealised pattern (shape only, not reach)". PNG export is client-side (`stage.toDataURL`).
6. **Saving.** The editor autosaves the whole item list (≤ 300 items) with the `version` it loaded; a stale version is `409 CONFLICT` (new error code) and the UI offers a reload. New items carry `new_`-prefixed temporary ids; the server returns an `idMap`. Only **structural** changes (items added or removed, a mic unit changed) are audited; moves, rotations and resizes are not, or autosave would flood the log.
7. **Read-only share links.** 32 random bytes, base64url, stored as-is (a leaked token exposes only what a database reader can already read), one live link per session, optional expiry, revocable. `getSharedSession(token)` is the **one documented exception** to ADR 0003's "context first": the token _is_ the authorisation, so it looks the link up with the raw client, then reads everything through `tenantDb({ organisationId })` for the link's own organisation and returns a deliberate projection (no ids, serials, notes, client name, and another session's name is never shown). Unknown, malformed, revoked and expired links all return the same 404. Responses are `noindex`, `no-referrer`, `no-store`. Free plans show "Planned with Kigumi"; Pro and above drop it (`Feature.UNBRANDED_EXPORTS`), for the PDFs too.
8. **Permissions and plans.** `VIEW_SESSIONS` (every role) and `MANAGE_SESSIONS` (owner, manager, engineer). Sessions, layouts, input lists, warnings, PDF, share links, DAW export and applying a recommendation are free. Four starter templates live in code and are free; saving, listing, editing and starting from **your own** templates is `Feature.TEMPLATES` (Pro).
9. **Applying a recommendation** (`planApply`, pure): the primary pick's units go onto an existing mic item that has the same `recommendationRef` or label (keeping its position); otherwise a new item is created in a staging row along the bottom edge of the room for the user to drag into place. **Nothing the model said is turned into coordinates**; its placement text goes into the channel's notes prefixed "AI placement:". Re-applying changes nothing; sources whose unit has left the locker, or that have no pick, are skipped and reported.

## Consequences

- 3D can read the existing rows with no migration.
- Five new tenant models, each with cross-organisation 404 tests on every route.
- One documented raw-client lookup (share tokens).
- The canvas has a keyboard-accessible twin (item list and numeric property fields), which also makes E2E practical.
- Duplicating a session copies its layout and microphones but not channel-owned fields (stand, preamp, notes); the duplicate overlaps the original in time, so the double-booking warning fires until the dates change.
- Times are stored in UTC and entered and shown in the studio timezone via `Intl` only (`src/lib/sessions/time.ts`); a session with no room uses Europe/London.
