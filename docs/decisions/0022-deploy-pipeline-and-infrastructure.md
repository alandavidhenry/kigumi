# 0022 — Deploy pipeline and infrastructure

**Status:** Accepted (2026-11-05)

## Context

Phases 0 to 8 ran only on a laptop and in CI. Launch needs a repeatable way to create the Azure resources and to ship each merge, with the same shape as Minato so one person can run both.

## Decisions

**Two environments, Development and Production.** Development deploys on every merge to `main` (`dev-deploy.yml`, after lint, tests, security scan and E2E). Production deploys when a GitHub release is published (`prod-deploy.yml`, same gates). `pr-check.yml` now runs on pull requests only, because the deploy workflows already run the same gates on `main`.

**Terraform for infrastructure, GitHub Actions for the app.** `infrastructure/` creates the resource group, App Service (Linux container), Key Vault, the app's storage account (versioning and 30-day soft delete, per ADR 0019), Azure Communication Services email, Log Analytics and Application Insights (ADR 0020), and in Production a separate backup account with an immutable `db-backups` container. Terraform sets the initial image only; deploys change it (`ignore_changes`).

**Secrets live in Key Vault.** App settings are Key Vault references; the App Service identity has `Key Vault Secrets User`. `BETTER_AUTH_SECRET` and `CRON_SECRET` are generated by Terraform, so nobody types them. `DATABASE_URL` (Neon) and the optional `ANTHROPIC_API_KEY` are passed in as secrets.

**Order inside a deploy:** `prisma migrate deploy` from the runner, switch the image and restart, then smoke test `/api/health/deep` with the bearer `CRON_SECRET` (ADR 0021 keeps that route closed to anyone else). Migrations must stay compatible with the previous release because the old container serves traffic while they run. Deploys to one environment are serialised.

**Left out on purpose.** No Postgres module (Neon, ADR 0001). No Document Intelligence, Gotenberg or AI Foundry (Minato only). No deployment slots or blue/green yet; a bad release is rolled back by re-running the previous deploy.

## Consequences

- A new environment is one `env/<Name>` folder plus a bootstrap for its state account.
- Terraform state holds secrets; the state accounts are private and only the CI service principal and the owner can read them.
- Azure Monitor alerts from `docs/operations.md` are still created by hand.
- First-time setup is a checklist in `docs/operations.md` ("Deploying").
