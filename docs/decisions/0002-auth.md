# 0002 — Auth: Better Auth with the organization plugin

**Status:** Accepted (2026-10-08). **Departs from Minato** (NextAuth v4 Credentials).

## Context

Kigumi is multi-tenant from day one: self-service sign-up, email verification, organisations, membership roles (Owner / Manager / Engineer / Viewer), email invitations and switching between organisations. NextAuth v4 only receives maintenance fixes, and Auth.js v5 never left beta (the Better Auth team now maintains it). Both would leave organisations, invitations and verification to be hand-built.

## Decision

- **Better Auth** with the Prisma adapter, email + password, required email verification, and password reset.
- **`organization` plugin** for `Organization`, `Member`, `Invitation` and `Session.activeOrganizationId`. Roles: `owner`, `manager`, `engineer`, `viewer`. `Organization` gets the extra field `planTier`.
- **`session.cookieCache`** enabled (short max-age) so most requests don't hit Postgres and Neon can still autosuspend.
- Emails (verification, reset, invitation) are sent through ACS via `src/lib/email.ts`. In development without ACS configured, they are logged with `console.warn`.
- Authorisation stays in our code: `src/types/rbac.ts` (role → permissions, `hasPermission`, same shape as Minato) and `requirePermission()` in `src/lib/tenant.ts`. `src/proxy.ts` only does an optimistic session-cookie check and redirects; every route and server component re-checks server-side.

## Consequences

- Minato's `auth.ts`, JWT callbacks and `getToken` proxy pattern do not carry over; the RBAC pattern does.
- Better Auth owns the shape of its tables. Renames must go through its config.
- OAuth providers (Google, Apple) can be added later without schema changes.
